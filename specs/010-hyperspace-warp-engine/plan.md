# Implementation Plan: Hyperspace Warp Engine

**Branch**: `010-hyperspace-warp-engine` | **Date**: 2026-08-06 | **Spec**: [spec.md](./spec.md)

## Summary

Triển khai hệ thống "Hyperspace Warp Engine" — một easter egg tích lũy năng lượng từ scroll velocity (Friction Accumulator), khi vượt ngưỡng chuyển toàn màn hình sang warp scene với speed-line particles, Cubi sprite biên độ giảm bay ngược chiều, kinetic strings giữ nguyên, và các HUD indicators nâng cấp. Ưu tiên tối thượng: tăng FPS thật sự khi warp bằng cách cull DOM sections phức tạp.

## Technical Context

**Language/Version**: TypeScript 5 / Next.js 16 (App Router)

**Primary Dependencies**: GSAP (ticker + animation), Lenis (scroll physics), Zustand (state), Canvas 2D API (warp overlay particles)

**Storage**: N/A (client-side only, no persistence)

**Testing**: Manual browser testing, FPS profiling với DevTools Performance tab

**Target Platform**: Web (Desktop primary, Mobile secondary) — Chrome/Edge/Safari/Firefox

**Performance Goals**: ≥ 50 FPS trên i7-7700 khi warp active; ≥ 60 FPS trên RTX 3060+

**Constraints**:
- 1 RAF duy nhất (GSAP ticker — không raw RAF song song)
- Không dùng useState/useContext cho scroll-linked data
- Không WebGL/Three.js
- Zero-cost: không thư viện/CDN trả phí mới
- Không break DOM scroll teleport system của Lenis
- Không CSS `filter: blur` hay opacity fade transitions theo constitution

**Scale/Scope**: 5 user stories, ~6 files mới/sửa, 1 component mới (WarpOverlay)

## Architecture Decisions

### A. Warp Pool — Friction Accumulator Pattern
- **Lưu trữ**: `warpPoolRef = useRef<number>(0)` trong `useExhibitionScroll` (KHÔNG Zustand — tần suất cao)
- **Update**: Trong GSAP ticker callback hiện có, mỗi frame:
  ```
  warpPool += Math.abs(velocity) * WARP_GAIN
  warpPool *= WARP_FRICTION  // decay
  warpPool = clamp(0, 1)
  ```
- **Constants**: `WARP_GAIN = 0.04`, `WARP_FRICTION = 0.96` (tunable)
- **Threshold trigger**: khi warpPool >= 0.85 → dispatch `setPhase('WARPING')` to Zustand

### B. WarpOverlay Canvas — Speed Lines System
- Canvas full-screen fixed, z-index 90 (dưới cursor z-100, trên sections z-50)
- Pool 120 WarpParticles, mỗi particle: `{x, y, vx, vy, length, alpha, hue}`
- Spawn ngược chiều scroll direction (velocity < 0 → particles bay lên)
- LOD: `particleCount = Math.min(120, Math.floor(fps / 60 * 120))` 
- Render trong GSAP ticker

### C. Cubi Amplitude Modulation (SpriteAnimation.tsx)
- Export `warpAmplitudeMultiplier` store value (0.10~1.0) thông qua Zustand `warpPool`
- Trong `getTrajectory()`: `moveX *= amplitudeMult`, `moveY *= amplitudeMult`  
- Khi warp: pool lerp → amplitudeMult lerp xuống 0.12 (12% biên độ gốc, không về 0)
- Thêm `offsetY -= velocity * WARP_DRIFT` để bay ngược chiều

### D. DOM Culling — Dual Method với Benchmark Flag
- `WARP_CULL_METHOD: 'opacity' | 'display'` constant trong WarpOverlay
- Method A (`opacity`): sections wrapper `style.opacity = '0'`
- Method B (`display`): sections wrapper `style.display = 'none'`
- Implement cả 2, default = Method B, test thực tế trên i7-7700

### E. Cursor Split Ring (CustomCursor.tsx)
- SVG viewBox 64x64, r=26, CIRCUMFERENCE = 163.36
- **Top half** (stroke từ 270° → 90°, tức 180° = CIRCUMFERENCE/2): FPS gauge — max 100 FPS
- **Bottom half** (stroke từ 90° → 270°, flip/rotate 180°): Warp gauge — max warpPool 1.0
- Màu warp: `warpPool < 0.3` → `#00F2FF`, `0.3-0.8` → `#FF8C00`, `> 0.8` → `#FF003C` + pulse
- Scale cursor SVG từ w-16 (64px) lên w-20 (80px) trên PC
- Thêm "WARP" label + percentage text bên cạnh FPS tag

### F. Mobile Auto-FPS + 5-tap Fix
- `MobileFpsOverlay`: subscribe to Zustand `currentPhase === 'WARPING'` → auto setIsVisible(true)
- 5-tap fix: kiểm tra `fps-tap-zone` bị `KineticStringsCanvas` (pointer-events-none đúng chưa?) hoặc overlay nào block. Thêm `style={{ touchAction: 'manipulation', zIndex: 210 }}` và đảm bảo không element nào có pointer-events: auto phủ lên.
